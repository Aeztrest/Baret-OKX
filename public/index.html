Vetra is a pay-per-call API that inspects an EVM transaction before it gets signed — unlimited approvals, blanket NFT operator grants, off-chain permits, proxy-upgrade and ownership calls, insufficient balance, blocklist hits. One call, one price, an answer: safe: true or safe: false with reasons.

How it works

Vetra never signs, never holds keys, and never submits anything on-chain. It only answers one question: is this transaction safe to sign?

01

Agent calls Vetra

Before signing, an agent sends the pending transaction (raw hex, or a {to, value, data} object) to Vetra's MCP tool or REST endpoint.

02

x402 pays per call

The call is metered with x402: no payment header → HTTP 402 with the price; a valid USDC payment → the check runs.

03

Agent gets a verdict

Vetra decodes the calldata, checks approvals and privileged calls on-chain, and returns safe, a risk level, and human-readable findings.

MCP (Agent-to-MCP)

A real Model Context Protocol server over Streamable HTTP at POST /mcp. initialize and tools/list are free; tools/call for check_transaction is gated by x402 at the HTTP layer, before the call ever reaches the tool.

// tools/list ->
{
  "name": "check_transaction",
  "description": "Analyze an EVM transaction BEFORE signing it...",
  "inputSchema": {
    "type": "object",
    "required": ["transaction"],
    "properties": {
      "network": { "type": "string" },
      "transaction": { "type": "object" },
      "userWallet": { "type": "string" }
    }
  }
}
